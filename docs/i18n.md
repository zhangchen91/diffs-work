# 全球化 / i18n（MessageFormat 2）

## 为什么用 MF2

界面文案里有复数、数字、日期、货币。Unicode **MessageFormat 2** 把这些放进消息本身（`.input` / `.match`），
翻译者不需要动代码，也不需要为每种语言写一套 `{count} 个` 的判断逻辑。

规范：https://messageformat.unicode.org/
实现参考：https://github.com/tomasr8/messageformat2 （Python，官方测试集通过；我们按其行为对拍语义）


## 已实现（MF2 子集）

| 能力 | 语法 | 例子 |
|---|---|---|
| 变量 | `{$name}` | `Hello, {$name}!` |
| 转义 | `\{ \} \| \\` | `a\{b\}` |
| 数字/整数/百分比/货币 | `{$n :number}` `:integer` `:percent` `:currency` | `{$n :number}` → `1,234.5` |
| 日期 | `{$d :date}` `:time` `:datetime` | 随 locale 变化 |
| 复数选择 | `.input {$n :number}` + `.match $n` + `one {{…}}` `* {{…}}` | 英文 one/other，中文恒 other |
| 精确键 | `0 {{none}}` `1 {{one}}` | 先精确匹配，再复数类别 |
| 局部变量 | `.local $n = {$count :integer}` | |
| bidi 隔离 | `formatMessage(src, vars, { bidi: true })` | 包 U+2068/U+2069 |
| 错误 | 缺变量保留 `{$name}` 并回报 | `onError` 收集 |

未实现：markup、attributes、自定义函数、`:offset`。需要时按 spec 增量加，测试先行。

## 接入方式

```tsx
import { useI18n } from "@diffs/i18n";

function Hero() {
  const { t, locale, setLocale } = useI18n();
  return <h1>{t("hero.title1")}</h1>;      // 纯文本
}

// 带参数 / 复数
t("xlsx.summary", { sheets: 4, added: 60, removed: 0, modified: 1 })
```

- 语言由 `localStorage["diffs.locale"]` 记住；首次访问按 `navigator.languages` 协商（`zh-*` → zh-CN，其它 → en）。
- 文案按语言**懒加载**（各自一个 chunk，gzip ≈ 7–9 KB），首屏不会为了另一种语言付费。

## 新增语言（社区口子）

1. 复制 `packages/i18n/src/messages/en.ts` 为 `messages/<tag>.ts`，翻译值（键不动）；
2. 在 `packages/i18n/src/index.tsx` 的 `LOCALES` 与 `MESSAGE_LOADERS` 各加一行；
3. `pnpm test:website` 会检查：
   - 两个语言键集合完全一致；
   - 没有任何空文案；
   - 每条消息都能解析并格式化（占位符都填得上）；
   - 英文目录里不残留中日韩字符（防止漏译）。
4. 文档站：`apps/docs/src/content/docs/<tag>/` 放同名 mdx 即可，侧栏与切换器自动出现。

## 验证命令

```bash
pnpm test:mf2       # MF2 运行时 16 例
pnpm test:website   # 编码 8 例 + i18n 7 例（键一致 / 无中文残留 / 全部可格式化）
```

线上验收：官网与本地站右上角切换中文/English；文档 `/` 与 `/en/` 互跳；刷新后语言保持。
