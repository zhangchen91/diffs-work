# 统一差异协议

所有文件类型产出**同一种差异结构**。新增一种格式，只要把它的原始格式映射到这份协议，
站点、插件、导出、测试都不用改。

## 四个动作

| 动作 | 含义 | 判定 |
|---|---|---|
| `add` | 新版多出来的内容 | 旧版没有对应 |
| `del` | 旧版有、新版没了的内容 | 新版没有对应 |
| `mod` | 同一处内容变了 | 有对应，文本不同 |
| `move` | 同一处内容换了位置 | 有对应，文本相同或相近，位置变了 |

**`mod` 可以退化。** 一种格式如果分不清「改了」和「删了再新增」，就输出 `del` + `add`，
协议层不要求所有格式都能产出 `mod`。

## 一个变更可以带多个动作

移动常常同时是修改：函数从第 10 行挪到第 40 行，里面的常量也从 `0.05` 改成 `0.08`。

```json
{ "ops": ["move", "mod"] }
```

`ops` 是数组，按重要性排序。只做了一件事就是单元素数组。**不要**用组合名（`move+mod`）——
那会让消费方必须穷举组合。

## 结构

```ts
interface DiffResult {
  engine: string;          // 谁产出的，用于排查
  kind: "code" | "sheet" | "opc" | "pdf" | ...;
  summary: string;         // 给人看的一句话
  changes: Change[];       // 全部变更，扁平列表
  totals: Record<Op, number>;   // 每个动作各多少处
}

interface Change {
  ops: Op[];               // 至少一个
  /** 在哪：文件/工作表/幻灯片/页。单容器格式用空字符串 */
  container: string;
  /** 位置上的是什么：单元格地址、行号、段落号。给人看的字符串 */
  where: string;
  /** 旧版内容。add 时为空 */
  before?: string;
  /** 新版内容。del 时为空 */
  after?: string;
  /** move 专用：从哪来、到哪去 */
  from?: string;
  to?: string;
}
```

`changes` 是**扁平**的，且**只放变更**。未变化的上下文行（`ctx`）不进 `changes`，它们属于
展现细节，需要时由展现层围绕变更自己取。分组（按工作表、按页）也由展现层做——不同格式的
自然分组不同，放进协议会让新格式被迫模拟别人的分组。

## 动作名只用四个

外部引擎的命名五花八门（`insert` / `ins` / `add` / `change` / `modify` / `rm` / `delete`），
协议层**统一**成四个，适配在自己的入口做：

| 引擎里可能叫 | 协议里 |
|---|---|
| `ins` `insert` `add` `added` | `add` |
| `del` `delete` `rm` `removed` | `del` |
| `mod` `change` `update` `changed` | `mod` |
| `move` `moved` | `move` |

样式变化不是内容变化，协议层**不含**样式。需要展示样式差异的格式，把它放进
`Change.detail` 这类附加字段，由该格式自己的渲染器用。

## 为什么这样定

- **动作只有四个**：任何文件类型的差异都能归到这四类，多一个都是负担。
- **`ops` 是数组**：移动带修改是真实场景，协议必须能表达，而不是让每种引擎自己发明组合。
- **`before`/`after` 是字符串**：Excel 单元格、Word 段落、PDF 文本行都是文本。要保留富信息
  （样式、坐标）就再多加字段，但基础形态一致。
- **扁平 + `container`**：分组交给展现层，新格式不背别人的包袱。

## 新增一种格式的步骤

1. 写一个 wasm，导出 `diff(a: Vec<u8>, b: Vec<u8>) -> String`，返回上面的 `DiffResult`
2. 在 `packages/formats/src/registry.ts` 注册扩展名 → 模块
3. 在 docs 站补一页说明
4. 加一个 `examples/<格式>/` 样例对

不需要改站点、插件或测试——它们只认这份协议。
