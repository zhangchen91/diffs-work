## 为什么值得做

法务与投研的日常是：一份合同在 Word 里改了七版，最后要回答「第七版相对第三版到底动了什么」。
现在的做法是关掉文档、打开浏览器、拖两个文件进去——步骤不多，但打断了正在做的事，
于是很多人在文档里用「比较文档」草草看一眼，而那恰恰是最不靠谱的一种读法。

## 打算怎么做

| 步骤 | 做什么 |
|---|---|
| 1 | 任务窗格里选「与我保存的某个版本比」或「与另一份文档比」 |
| 2 | 用 Office.js 拿到两份文档的 OOXML 包（`.docx` / `.xlsx` 的 zip） |
| 3 | 交给本地站（`127.0.0.1:5279`）或本站的 wasm 内核比对 |
| 4 | 结果以**列表 + 定位**的方式出现在任务窗格：点一条跳到一个段落 / 一个单元格 |

## 会不会有新的泄露风险

这是我们要先说清楚的一点：**不会把文档发到云端**。

- 走本地站时，文档只在你的机器上，路径也不经过第三方；
- 走本页内核时，文件在浏览器内存里，网络面板可以自证；
- 加载项本身不需要任何「文档内容上传」权限。

加载项要申请的最小权限是 `ReadDocument`（Word）/ `ReadWriteDocument`（Excel 仅在需要跳转定位时）。

## 现在能做的替代流程

1. 在 Word 里「另存为」两个版本（或直接用 git / 网盘里的历史版本）；
2. 打开 diffs.work，拖进去；
3. 看完把结论带回文档。

在加载项上线之前，这三步已经是完整的、可复核的流程——加载项省的是**切换成本**，不是能力。
