这是 [什么是「可验证」](/concepts/verification/) 的操作版。不需要先读那篇，照着做也能工作。

## 交付时（Agent 侧）

- [ ] 附上**改动前**与**改动后**的文件，或一个 git 提交
- [ ] 附上 `diff_compare`（或 `diffs diff`）的**原始结果**，不是摘要
- [ ] 用「第 N 行」而不是「共 N 处」来指位置
- [ ] 位置变了的内容说「移动」，不说「删除 + 新增」
- [ ] 工具报错就贴原始错误，不编造结果

## 复核时（人侧）

- [ ] **在另一个工具里重算一次**——不用 Agent 自己的工具
- [ ] 先看分布（改了哪几个函数 / 段落 / 表格 / 幻灯片），再看内容
- [ ] 对每一处「改」，看被改的那**几个字**，而不是整行
- [ ] 对每一处「移」，确认**移到这里的那份内容没被顺手改动**
- [ ] 检查有没有**新增的依赖、import、外部链接**
- [ ] 空白行、缩进、行尾的变化不占用注意力（工具已经过滤，若大量出现，说明两侧来源不一致）

## 三分钟版本

> 下面用 `diffs <命令>` 表示 CLI。它**还没发布到 npm**，所以请先 `pnpm build:cli`，
> 再把 `diffs` 换成 `node apps/cli/lib/bin.js`。

```bash
# 1. 重算
diffs diff before.ts after.ts

# 2. 只看结构：改了哪些行、有没有整块搬家
diffs diff before.ts after.ts --json | jq '.counts'

# 3. 需要给别人看时，打开本地站
diffs diff --open before.ts after.ts
```

<Callout tone="rule" title="一条就够了。">
如果只能做到其中一件事：**在第三方工具里重算一次 diff**。
它比「再读一遍描述」有用得多，也比「让它自检」可信得多。
</Callout>

## 什么时候可以不看

- 改动是**纯新增**（新文件、新目录），且不涉及已有文件的删除或修改；
- 改动只发生在**文档注释 / README**，且不涉及任何命令、路径、参数；
- 改动已被一个**独立来源**验证过（例如上游发布的官方变更说明）。

除此之外，「我检查过了」这句话不构成复核。
