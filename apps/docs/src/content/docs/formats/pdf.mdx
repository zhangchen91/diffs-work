PDF 不是「一种排版好的文本」，它是**页面上的字形与其坐标**。
所以 PDF 的比对必须先回答一个问题：这两页上，哪几行文字变了、它们在哪里。

## 用什么比

1. 用 pdf.js 抽出每页的**文字层**：每段文字 + 它在页面上的坐标框；
2. 按纵向位置把文字聚成**行**（同一行的小片段合并）；
3. 对两边的行序列做与代码相同的行级比对（相同 / 删 / 加 / 改 / 移）；
4. 把每一处改动映射回**坐标框**，在渲染出的页面上画出来。

没有文字层的页（扫描件）**不做比对**：工具会明确列出是第几页，而不是给出一份「没有差异」的结果。

## 怎么判

- **行**是比对单位：行内同一个字变了也只会标出这一行；
- 行位置的轻微像素差（同一段文字整体上下挪了 1pt）不判为变化；
- 跨页的内容当作两页分别处理，不会把「整段换页」识别成移动——这是当前的已知限制。

## 结果长什么样

```jsonc
{
  "kind": "pdf",
  "pages": [
    { "index": 3, "changed": true,
      "boxes": [ { "x": 72, "y": 583, "w": 322, "h": 12, "op": "mod" } ] }
  ]
}
```

坐标单位是 PDF 用户单位（1/72 英寸），原点在页面左下角。

## 看不到什么

| 看不到 | 为什么 |
|---|---|
| 字体的细微替换 | 字形变了但文字没变，不算内容改动 |
| 图片内部的差异 | 属于图片比对 |
| 加密 / 带权限口令的 PDF | 无法解析；会明确报「需要口令」 |
| 表单域的当前值 | 字段值会读，但字段的「默认值」变化不计 |

<Callout tone="warn" title="扫描件目前不支持。">
有文字层的 PDF 才能做对象级比对。扫描件（整页是图片）会被明确列出页号并说明无法比对——
**不会**返回一个看起来「没有差异」的空结果。OCR 在产品里还没有实现，
仓库里的 `tessdata` 模型是为后续准备、当前未被调用。
</Callout>

## 常见问题

**整页都是框？** 说明这一页在两边没有行对齐上（常见于重新排版的 PDF）。先看是不是重新导出导致的换行变化。

**扫描件和电子版对比？** 目前**做不到**：扫描件没有文字层，会被直接列为无法比对。要核对两份扫描件，先各自转成带文字层的 PDF 再比。
