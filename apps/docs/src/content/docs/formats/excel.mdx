表格的难点不在「哪个格子不一样」，而在**行被插入 / 删除之后，下面的格子全都位移了**。
按坐标比会得到一整片红色。所以先对齐行，再比格子。

## 用什么比

直接读 OOXML 的 `xl/worksheets/sheetN.xml` 与共享字符串表：

- 单元格的**值**（数字、文本、日期、布尔）；
- 单元格的**公式**（`<f>`）与缓存值分开报；
- **合并单元格**的范围；
- 工作表的新增 / 删除 / 重命名。

不读：列宽、行高、打印区域、条件格式的样式细节——除非你要看「只改了格式」的情况（见下）。

## 怎么判

<Doc kind="step" n="1" title="先对齐行" />

用每行的**首列（或整行拼接）**作为身份键做对齐，找到被插入、删除、移动的行。
有了这一步，行下面所有格子的「位移」就不会被误判成改动。

<Doc kind="step" n="2" title="再比格子" />

同一行内的格子逐个比：新增、删除、改值。数值与文本严格区分（`1` 与 `"1"` 不同），
日期按实际日期值比较而不是显示格式。

<Doc kind="step" n="3" title="公式单独说" />

公式变了、缓存值也变了 → 报「公式变化」，并把两侧公式都显示出来。
只改了公式但值没变（例如把 `=A1` 改成 `=$A$1`）→ 仍然报出来，因为这是实质改动。

<Doc kind="step" n="4" title="只改样式" />

格式变化（数字格式、填充色、字体）默认**不**进入变更清单；需要看时打开「显示样式变化」。
理由：财务模型的颜色标记常常有人手工调，混进变更清单会淹没真正的数值改动。

## 结果长什么样

```jsonc
{
  "kind": "xlsx",
  "sheets": [
    { "name": "报价", "status": "changed", "added": 2, "removed": 1, "modified": 3,
      "changes": [
        { "ref": "D12", "op": "mod", "old": "1,200,000", "new": "1,350,000" },
        { "ref": "E7",  "op": "formula", "old": "=SUM(D2:D6)", "new": "=SUM(D2:D7)" }
      ] }
  ]
}
```

## 看不到什么

| 看不到 | 为什么 |
|---|---|
| 图表数据源之外的变化 | 图表本身是独立的 XML 部件，暂不参与比对 |
| 数据透视表缓存 | 缓存由 Excel 生成，不属于内容 |
| 宏与 VBA | `.xlsm` 的 VBA 部件不比对（比对的是数据） |
| 隐藏工作表的内容 | 会比对，并在结果里标出该表是隐藏的 |

<Callout tone="warn" title="`.xls`（2003 及更早）不支持。">
那是二进制 BIFF 格式，不是 zip。我们不会假装能读它——这类文件会明确显示「不支持」，
请先另存为 `.xlsx`。
</Callout>

## 常见问题

**整表都变了？** 多半是重算导致的缓存值全部变化（例如打开时按了 F9），或两次导出的日期格式不同。
可以只打开「公式变化」筛选来看。

**行顺序变了但内容没变？** 会报成移动，而不是「整片删除 + 新增」。
