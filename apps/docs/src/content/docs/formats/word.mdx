Word 是复核里最容易出事的一类：**改一个数字、删一个「不」、挪一段条款**，在排版上几乎看不出来。
所以 Word 视图不追求「像 Word 那样好看」，只回答三个问题：哪一段变了、这一段里哪几个字变了、哪一段搬了家。

## 用什么比

只读 OOXML 里真正承载内容的那部分：

- `word/document.xml` 里的段落（`w:p`）与文字（`w:t`）；
- 表格按行展开成段落参与同一套对齐；
- 「段落编号」在结果里是**文档中段落的序号**（从 1 开始），不是 `w:p` 在 XML 里的出现顺序。

不读：字体、页边距、主题、图片二进制、页眉页脚版式。这些差异会被忽略——它们在复核时几乎总是噪声。

## 怎么判

<Doc kind="step" n="1" title="段落对齐" />

两边段落各自成序列，先按**完全相同**配对（LCS），再对未配对的连续段做「同一段落被改写」的判定：
两段有足够长的公共前后缀就是**改**，否则是一次**删除 + 一次新增**。

<Doc kind="step" n="2" title="段内逐字" />

一对「改」的段落，改动位置同样来自它们的公共前后缀；两侧各自标出丢失 / 新得的字。

<Doc kind="step" n="3" title="段落搬家" />

同一段文字在原处消失、在别处原样出现 → **移动**，并写明「移自第 N 段 / 移至第 M 段」。
注释、空白段落不参与搬家判定。

## 结果长什么样

```jsonc
{
  "kind": "docx",
  "revisions": [
    { "kind": "update", "paragraph": 12, "old": "…交付期限为 30 日…", "new": "…交付期限为 45 日…",
      "segments": [ { "op": "same", "text": "…交付期限为 " }, { "op": "ins", "text": "4" }, { "op": "same", "text": "5 日…" } ] },
    { "kind": "move", "from": 5, "to": 9, "text": "争议解决：" }
  ]
}
```

## 看不到什么

| 看不到 | 为什么 |
|---|---|
| 字体 / 字号 / 颜色变化 | 复核关心的是内容，不是排印 |
| 页眉页脚的「第 x 页共 y 页」变化 | 域代码每次打开都会变，属于噪声 |
| 图片的像素级差异 | 属于图片比对，是另一件事 |
| 修订痕迹的作者与时间 | 我们比对的是两份文件，不是 Word 的修订记录 |

<Callout tone="note" title="那还用不用「保留修订痕迹」的 Word 文件？">
不用。把两份**干净版本**（各自接受全部修订后的文件）交给它，得到的结果比 Word 自己的修订视图更稳定：
Word 的修订记录依赖编辑过程，两份文件各自保留各自的修订历史时，反而无法对齐。
</Callout>

## 常见问题

**段落数对不上？** 空白段落会被忽略；只含域代码的段落也会被忽略，因此序号可能与 Word 里看到的不同。

**整篇都显示为「删 + 加」？** 多半是两次导出的行尾或全半角不一致（例如从 PDF / 网页复制过），
文字本身不同会让每一段都判成「删 + 加」。先把两边统一成同一来源再比。

**表格里的改动？** 表格按行展开，改动落在具体单元格的段落上，视图会显示所在表格的第几行。
