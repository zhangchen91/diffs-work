The hard part of a spreadsheet is not "which cell differs" but that **once a row is inserted or
deleted, every cell below it shifts**. Comparing by coordinates gives you a solid wall of red. So
rows are aligned first, and only then are cells compared.

## What it compares

It reads the OOXML `xl/worksheets/sheetN.xml` and the shared string table directly:

- a cell's **value** (number, text, date, boolean);
- a cell's **formula** (`<f>`), reported separately from the cached value;
- the ranges of **merged cells**;
- worksheets being added / deleted / renamed.

Not read: column widths, row heights, print areas, style details of conditional formatting — unless
you want to see the "formatting only" case (see below).

## How it decides

<Doc kind="step" n="1" title="Align rows first" />

Each row's **first column (or the whole row concatenated)** is used as an identity key for alignment,
identifying inserted, deleted and moved rows. With this step, the "shift" of every cell below a row
is not mistaken for a change.

<Doc kind="step" n="2" title="Then compare cells" />

Cells within the same row are compared one by one: added, removed, value changed. Numbers and text
are strictly distinguished (`1` and `"1"` differ), and dates are compared by their actual date value
rather than by display format.

<Doc kind="step" n="3" title="Formulas get their own line" />

Formula changed and cached value changed → reported as a "formula change", with both formulas shown.
Only the formula changed but the value did not (for example `=A1` became `=$A$1`) → still reported,
because it is a substantive change.

<Doc kind="step" n="4" title="Style-only changes" />

Formatting changes (number format, fill colour, font) do **not** enter the change list by default;
switch on "show style changes" when you need them. The reason: colour-coding in financial models is
often adjusted by hand, and mixing it into the change list drowns the real numeric changes.

## What the result looks like

```jsonc
{
  "kind": "xlsx",
  "sheets": [
    { "name": "Quote", "status": "changed", "added": 2, "removed": 1, "modified": 3,
      "changes": [
        { "ref": "D12", "op": "mod", "old": "1,200,000", "new": "1,350,000" },
        { "ref": "E7",  "op": "formula", "old": "=SUM(D2:D6)", "new": "=SUM(D2:D7)" }
      ] }
  ]
}
```

## What it cannot see

| Cannot see | Why |
|---|---|
| Changes outside a chart's data source | The chart itself is a separate XML part and does not take part in the comparison yet |
| Pivot table caches | The cache is generated by Excel and is not content |
| Macros and VBA | The VBA part of `.xlsm` is not compared (the data is) |
| The contents of hidden worksheets | They *are* compared, and the result marks the sheet as hidden |

<Callout tone="warn" title="`.xls` (2003 and earlier) is not supported.">
That is the binary BIFF format, not a zip. We will not pretend to read it — such files are shown
explicitly as "not supported"; please save them as `.xlsx` first.
</Callout>

## Common questions

**The whole sheet looks changed?** Most likely a recalculation changed every cached value (for
example, F9 was pressed while the file was open), or the two exports use different date formats. Try
filtering to "formula changes" only.

**Rows reordered but content unchanged?** That is reported as a move, not as a "delete everything and
add everything".
