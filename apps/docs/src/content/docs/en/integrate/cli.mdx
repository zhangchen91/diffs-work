## Commands

| Command | What it does |
|---|---|
| `diffs diff <old> <new>` | Compare two files in the terminal |
| `diffs diff <old> <new> --unified` | Output a standard unified diff (ready for `patch`) |
| `diffs diff <old> <new> --json` | Output the full JSON (see [portable@1](/en/reference/portable/)) |
| `diffs diff <file> --revision HEAD~1` | The working file against a commit |
| `diffs diff <old> <new> --context 5` | Lines of context per hunk (0–20, default 3) |
| `diffs diff <old> <new> --maxHunks 5` | Cap on the number of hunks (1–200, default 40) |
| `diffs diff --open <old> <new>` | Open the result in the local site |
| `diffs local [--port 5279] [--no-open]` | Start the local site (default) |
| `diffs inbox [--open]` | Start and jump straight to Inbox: comparisons delivered by the agent / extensions collect here |
| `diffs paths` | Print the data directory (`~/.diffs`) |
| `diffs version` | Print the version |

<Callout tone="warn" title="The CLI is not on npm yet.">
The `diffs` package on npm belongs to **someone else and is unrelated**. `npx diffs` installs that,
not this tool. Until it is published, the commands are relative to the repository:

```bash
pnpm build:cli
node apps/cli/lib/bin.js <command>
```

The table below writes `diffs <command>`; substitute the line above.
</Callout>

## Local site

`diffs local` listens only on `127.0.0.1:5279` and is not exposed externally. It provides:

| Endpoint | Method | What it does |
|---|---|---|
| `/api/health` | GET | Liveness and version |
| `/api/diff` | POST | Compare two contents (file paths or inline content) |
| `/api/open` | POST | Open an existing comparison result in the local site |
| `/api/inbox` | GET / POST | List / deliver one pending comparison |
| `/api/file` | GET | Read a local file (so the view can show the original) |
| `/api/pair` | POST / GET | Stage a pair of contents for the browser extension to retrieve (`#/compare?pair=<id>`) |

```bash
curl -s http://127.0.0.1:5279/api/health
```

### Delivering a comparison to Inbox

```bash
curl -s http://127.0.0.1:5279/api/inbox \
  -H 'content-type: application/json' \
  -d '{
    "title": "Contract v3 → v4",
    "old": { "label": "v3", "path": "/tmp/contract-v3.docx" },
    "new": { "label": "v4", "path": "/tmp/contract-v4.docx" },
    "source": "ci"
  }'
```

<Callout tone="note" title="Inbox is a queue for humans.">
Every time the agent calls `diff_compare` it delivers an entry along the way; open the local site and
you can see the side-by-side view of that pair, without scrolling back through chat history.
</Callout>

## Where the data lives

`diffs paths` prints `~/.diffs`. It holds only the Inbox index and the comparisons you delivered — no
cached file bodies.

## Exit codes

| Code | Meaning |
|---|---|
| `0` | Success (**regardless of whether the two contents are the same**) |
| `1` | Bad arguments / file not found / cannot parse |
| `2` | Internal error |

Deliberately, "there are differences" is not a non-zero exit code: in a script, `set -e` would abort
because "differences were found as expected", which is almost always collateral damage. Check
`summary` yourself if you need to.
